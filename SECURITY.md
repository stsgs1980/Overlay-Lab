# Security Policy

## Поддерживаемые версии

Проект развивается в ветке `main`; исправления выходят в последней версии.
Форки и деплои поддерживаются владельцем форка.

## Как сообщить об уязвимости

Публичные issue для уязвимостей не используйте. Приватный канал:

1. Откройте вкладку `Security` в репозитории проекта.
2. Нажмите `Report a vulnerability` (GitHub Private Vulnerability Reporting).
3. Опишите шаги воспроизведения, влияние и, если есть, предложение по исправлению.

Первый ответ — в течение 7 дней. После исправления информация попадает в `CHANGELOG.md`.

## Что относится к политике безопасности

- Тулчейн: ESLint (включая `eslint-rules/`), Prettier, Stylelint, markdownlint,
  Vitest, Husky и скрипты в `scripts/`.
- Конфигурация CI (`.github/workflows/ci.yml`): утечки секретов, избыточные права.
- Зависимости времени выполнения (`dependencies`): Next.js, React, базовые UI-библиотеки.

## Что не относится

- Уязвимости npm-пакетов: сообщайте разработчикам пакета; обновления приходят
  через Dependabot (`.github/dependabot.yml`).
- Витрина — полностью статическое приложение без бэкенда и без секретов;
  пользовательские данные не собираются и никуда не отправляются.

## npm audit

Снимок на 2026-11-09 (Node.js 24.15.0, npm 11.12.1). Воспроизведение:

```bash
npm audit --omit=dev --audit-level=high
npm audit
```

```text
production-дерево (omit=dev): 0 vulnerabilities
полное дерево:                  0 vulnerabilities
```

Advisory GHSA-g3hv-75wg-m249 (minimatch, moderate DoS) закрывается override
`minimatch >=11.0.1` в `package.json`; для `eslint-plugin-jsx-a11y`, который
объявляет `minimatch ^3.1.2` вне уязвимого диапазона (7.0.0–11.0.0), действует
точечный override на `^3.1.2` — глобальный пин ломал бы плагин в рантайме.
